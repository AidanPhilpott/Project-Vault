# Stage 1: Individual interview analysis

**Input:** one transcript. **Output:** `research/analysis/YYYY-MM-DD_role-name.md`, following `template.md` in this folder.

## Instructions

1. **One transcript per run.** If given several, do them one at a time, each as its own run and file. Batching produces noticeably worse analyses.
2. Read the whole transcript before writing anything.
3. Fill every section of `template.md`. Label every theme, pain point and surprise `Explicitly stated` (the participant said it) or `Inferred` (your interpretation). Never upgrade an inference to stated.
4. **Quotes are verbatim.** Don't tidy grammar. If you can't find an exact quote to support a theme, say so rather than paraphrasing it into quotation marks.
5. Aim for 3–5 themes, 5–8 quotes and up to 5 pain points. Fewer is fine if the interview is thin; don't pad.
6. Preserve the inconvenient: points that contradict the team's assumptions go in **Surprises**, even if they're mentioned only once.
7. Leave the participant profile fields `TBD` where the transcript doesn't say. Don't guess roles or seniority.
8. After writing, point out anything that should go into project context (new terms → glossary, new people, open questions) and offer to route it via `pos-intake`.
