# Close-out

**This folder exists from day one, on purpose.** A project knowledge base rarely fails by never getting started. It fails by stopping about three weeks before the work does. The final stretch is the least documented and the most decision-dense part of a project: handoffs, ownership transfers, "we'll remember that." A decision made in the final week has no follow-up meeting to bring it back up. It gets written down then or it's gone.

**The one rule: documentation discipline goes up in the final weeks, not down.**

| File | When | Template |
|---|---|---|
| `CHECKLIST.md` | Read at kickoff. Run the timeline/scope-change steps each time a change is agreed, and the rest in the final two weeks. | It's a checklist |
| `YYYY-MM-DD_retrospective.md` | At close, before people disperse | `_templates/retrospective.md` |
| `YYYY-MM-DD_feedback-and-outcomes.md` | Add as feedback arrives, finalize at close | `_templates/feedback-and-outcomes.md` |
| `YYYY-MM-DD_deliverables-index.md` | Final week | `_templates/deliverables-index.md` |
| `communications/` | Copies of the wrap-up messages actually sent | n/a |

If the project never formally closes (it becomes ongoing, gets absorbed, or is cancelled), write two paragraphs here saying so and why. "This ended without a close-out" is itself a useful record.
